# Portfolio localization

English retains the existing URLs. Other languages use `/es`, `/de`, `/fr`,
`/it`, `/ar`, or `/fa` followed by the page path (for example `/fa/projects`).
The header switcher keeps the current page and project query. Explicit URLs
determine the language; there are no browser-language redirects.

## Editing copy

- Keep shared project, résumé and section structure in `app/assets/data/`.
- Keep identity/contact details in `app/assets/data/identity.ts`, page metadata
  in `app/assets/data/pageSeo.ts`, and supported languages in `shared/locales.ts`.
- `english.ts` combines canonical source strings with short interface copy.
- Edit visitor-facing copy by its readable key in `locales/{code}.ts`, including
  `locales/en.ts` for English. English falls back to its source string when
  there is no editorial override. Keep source strings stable: they also serve
  as lookup IDs for components, so changing them requires updating all usages.
- Write natural, language-specific copy rather than translating slogans
  literally. Keep experience, project status and technical claims factual.
- In a component, use `usePortfolioI18n().c("English interface copy")`.
- For canonical arrays/objects, use `usePortfolioI18n().content(source)`;
  this returns a computed value. IDs, links and technical codes stay unchanged.
- Use `localePath(...)` for every internal page link. Never prefix URLs by hand.

The source-text lookup is generated from readable keys, so repeated text uses
the same translation without duplicating content across Home and other pages.
Missing translations fall back to English. Technology/product names, source
code and filenames deliberately remain unchanged. The downloadable résumé PDF
remains English and is labelled accordingly on other language pages.

## RTL and animations

Arabic/Persian set `html` language/direction during SSR, use Vazirmatn, and load
the matching Quasar language pack. RTL CSS is generated by `postcss-rtlcss`.
Code/email fields are isolated as LTR; editable prose uses automatic bidi.
The hero technology list and its translated tagline are separate bidi groups.
Both align with the heading in RTL and wrap without mixing reading directions.
Typing reveals graphemes in reserved whole-word boxes to retain joined Arabic
letters and stable line wrapping. Glitches use Arabic/Persian character pools
and render whole segments, preserving accent colors and restoring original text.
Typing completion is per language and visit, while reduced-motion preferences
are respected. Locale changes remount pages but project-query changes do not.

## Checks

Run `npm run test:i18n`, `npm run typecheck` and `npm run build`. Review long translations at mobile
widths and verify language switching from a selected project. Translations are
an initial localization pass; native-speaker editorial review is recommended.
